# ADR 0005：对第三方资源保持中立（不内置任何入口）

## 背景

- 本产品的音源能力**完全来自社区插件**，而这些插件指向的内容可能涉及版权。
- 契约 v0.2 的风险表里曾把「内置 1–2 条示例订阅」列为冷启动的缓解手段。
- 这一步是敏感行为：预置入口 = 我们主动为特定第三方资源背书，并在 UI 上把它呈现为
  「官方推荐」。收益（少一次点击）与责任（替用户做了选择）完全不对等。

## 决策

1. **不内置任何第三方资源入口**：没有默认订阅列表、没有预置插件仓库、没有推荐位、
   没有「官方插件」概念、不内置任何市场内容。
2. **导入一律由用户主动发起**：本地文件 / 目录 / 压缩包 / URL / 粘贴文本；
   从哪来由用户决定，应用不替他决定。
3. **用户动作之前零外部请求**：启动、搜索、推荐、榜单、皮肤列表都不会访问任何第三方地址。
   只有用户添加并启用插件、且该插件被调用时，才按清单 `@hosts` 白名单发起请求。
4. **不做内容聚合分发**：我们不托管、不镜像、不索引第三方插件与皮肤。
   `repository.json` 只是**格式**约定——谁发布谁的仓库，用户自己填地址。
5. **界面与文档只用中性示例**：文档示例一律 `example.com` 占位；随仓库的 demo 插件
   只播放随包测试音频，不解析任何真实音源。
6. **明确的第三方免责声明**：插件导入界面与文档都要说明「插件由第三方提供、与本软件无关，
   请自行确认你有权访问相应内容」。

## 后果

- **冷启动确实更难**：新用户装完是 0 插件。缓解方式**不含**推荐资源：
  · 无插件时应用本身可用（本地文件播放、播放器、歌词、皮肤、本地库）；
  · 插件页给出「三种导入方式」与中性说明，**不写任何具体第三方地址**；
  · 文档提供插件格式说明与作者工具，便于社区自行传播。
- 我们不再维护策展内容，也就没有「推荐了侵权源」的责任面；同时不需要为社区仓库的
  可用性、安全性、合法性负责。
- `plugin.subscriptions.*` 命令**保留**（这是「用户自己填 URL」的机制），但没有默认值，
  首次使用时订阅列表必然为空。

## 红线（后续不得违反）

- 不在代码、注释、文档、i18n 文案、示例数据里写入**任何具体第三方音源/资源地址**
  （`example.com` 与 `127.0.0.1` 占位除外）。
- 不因「提升冷启动体验」而重新引入预置清单或推荐位。若产品确实需要，
  必须**另开 ADR 并先做合规评估**。
- 不把第三方来源包装成官方能力：UI 上不得出现「官方」「推荐」「精选」这类措辞指向第三方资源。

## 重新评估的触发条件

- 我们官方运营**自有版权内容**（自有素材/自有曲库）——那是另一回事，可另立入口与协议；
- 若取得明确的法律意见，界定清楚「预置策展清单」的合规边界，可重新评估（仍需新 ADR）。
