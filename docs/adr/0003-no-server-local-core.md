# ADR 0003：不提供服务器——本机核心 + Tauri IPC

## 背景

三条产品约束被明确：

1. **不提供服务器**：插件、皮肤等资源靠 git clone 分支获取，或用户手动下载/分享他人资源；
   我们不做市场后端。个人本地电脑使用。
2. **不需要账户服务**：将来若同步用户自己的歌单（如网易云音乐个人账户），那是**用户自己的
   第三方账号**，凭据存本机，不经我方任何服务。
3. **桌面端软件，无 web 端**：契约的唯一消费者是本机前端。

这三条合起来取消了「后端」这个对象本身：没有网络边界，也就没有 HTTP 语义负担。

## 决策

1. **不提供任何服务器**：无账号体系、无市场后端、无遥测上报。
2. **架构改为 Rust 本机核心 + Tauri IPC**：命令（`invoke`）与事件（`listen`），
   无 HTTP、无端口、无 CORS、无 JWT。
3. **社区资源只支持通用导入**：本地目录 / 压缩包 / URL / 粘贴文本四种来源统一为
   `ImportSource`。社区仓库由用户自行 clone 后指向目录，**应用不内建 git 客户端**
   （避免让用户装 git，也不背 libgit2 的体积与凭据复杂度）。
4. **插件运行时用内嵌 QuickJS**：贡献者写 JS/TS 即可，宿主只注入白名单能力
   （受限 `fetch`、`crypto`、`console`、插件私有 `storage`、`credentials`），无 fs/process。
5. **皮肤是惰性 JSON 文档**：导入导出即分享，导入做结构 + **令牌键名白名单**校验。
6. **第三方凭据只进 OS keyring**，按插件作用域隔离，日志与 SQLite 永不出现明文。

## 与之配套的删除（相对 ADR-0001 的实现）

| 删除 | 原因 |
|---|---|
| `auth.*`（登录/刷新/登出/资料） | 无我方账号体系 |
| JWT、限流、CORS、helmet、幂等键、游标分页的跨请求语义 | 无网络边界 |
| HTTP 契约与 OpenAPI-over-HTTP 代码生成 | 唯一消费者是本机前端，改用 specta 生成 TS 绑定 |
| Postgres / Redis / BullMQ / Docker / compose | 单机：SQLite + 本地文件 + tokio 任务足够 |
| WebSocket 实时通道 | 改用 Tauri 事件 |

产物处置：TS 骨架归档 `docs/archive/server-ts/`，旧 HTTP 规范归档
`docs/archive/contracts/backend-api-http.md`（仅作历史参考）。
新契约：`docs/contracts/local-core-api.md`。

## 新增的必需能力（原契约里没有）

- **本地曲库扫描**（目录扫描 + 元数据/音频探测）——Rust 的强项，且是「本地播放器」的核心；
- **插件导入与同意流程**（`plugin.preview` → 用户确认权限 → `plugin.import`）；
- **凭据管理**（keyring 写入/读取状态，永不回显值）；
- **诊断**（`system.status` / 打开日志目录），因为无遥测意味着问题只能靠用户本地日志定位。

## 后果与风险

- **社区资源 = 不可信代码**：沙箱与安装期同意从「可选增强」变成**必需项**。不执行安装脚本、
  不自动更新、URL/压缩包导入记录校验和并在变化时告知。
- **无遥测**：线上问题无法自动发现，只能依赖诊断页 + 用户提供日志；日志需按天滚动并可一键打包。
- **端点清单需要按新形态裁剪**：原 41 条中 `auth.*` 删除、市场写操作改为导入/导出，
  其余保留语义但换传输。

## 重新评估的触发条件

- 需要**多设备同步**或**官方市场**（集中索引、审核、签名分发）→ 回到「本机核心 + 远端只读/写入 API」两段式；
- 需要服务端音频转码集群 → 仍是 Rust，不改变本决策；
- 分发方式改为容器/浏览器访问 → 本 ADR 的核心前提（桌面软件）不成立，需重新评估。
