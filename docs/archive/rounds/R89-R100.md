# 第八十九～一百轮（归档）

> 迁出原因：STATE.md 的自报预算放不下更多轮次。结论与后续影响已经并进 STATE 的轮次表与 GOTCHAS：
> R89 的数据迁移校验（逐库 `quick_check` + 旁挂文件按后缀跳过）与 R90 的 `pet_invoke` 独立入口都还在用。

## 第九十轮

> 起点：R89 的三件事清完之后，`pet-core` 有了地基与守卫，差的是**宿主桥**。
> 目标（M1）：让宠物从「文档里的一只」变成「能画出来、能点、能跨会话记住你」，
> 同时**不碰音乐核心**、不默认暴露给 1.x 用户。

### 1. 本轮做了什么

| 层 | 改动 |
|---|---|
| 核心（pet-core） | 新增 `dispatch.rs`：`pet.state / pet.install / pet.tick / pet.setActive / pet.interact / pet.remove` 六条命令，参数 camelCase，**时间由调用方给**（可复现）；`contract.rs` 登记这 6 条；`Frame/Rect` 可序列化；`Engine::text_key` 暴露气泡文案键（核心只给键，文案在宿主 i18n） |
| 宿主（src-tauri） | `AppState` 增加宠物引擎（`Arc<Mutex<pet_core::Engine>>`），库落在 `<data>/pet/pet.db`；新增**独立入口** `pet_invoke{command, params}`（与 `core_invoke` 并列，不是它的分支），信封形状与音乐核心一致、错误码是 `pet.*`；宠物库打不开时降级为内存引擎并记日志 |
| 前端 | `src/services/core.pet.ts` 门面（浏览器预览如实报 `unsupported_platform`）；`src/pet/builtin.ts` 内置宠物（**程序化渲染**：核心出帧 → CSS transform + 气泡；点击 = `touch`）；`ui.petEnabled`（默认关，持久化）；App 只在开关打开时注册内置宠物，关掉即注销；设置页新增「实验（预开发）」卡片 |
| 守卫 | `check:reachability` 增加宠物域：命令必须有服务封装 + 有界面调用，或登记进 `DELIBERATE_PET`；当前留白 `pet.state` / `pet.remove`（M2 的管理面板用） |

  喂食冷却报错而触摸静默、删掉出战宠物后 `active` 为空且不能再 tick、`tick` 帧字段齐全且气泡回键）；
- `pnpm smoke`：**483**（+5：开关默认关/可开、浏览器下宠物命令如实报不支持、内置规格自洽、内置宠物注册后宿主出现容器）；
- `pnpm check:contract`：宠物域 6 条命令 / 6 个错误码双向一致；`pnpm check:reachability`：6 条命令可达或已登记留白；
- `pnpm verify`：7 道全绿；
- 打包版实测（真实 WebView2 + 真实数据目录）：
  | 文件 | 内容 |
  |---|---|
  | `r90-settings.png` | 设置页新增「实验（预开发）→ 宠物」开关，默认「禁用」 |
  | `r90-pet-on.png` | 打开开关后右下角出现内置宠物（程序化渲染，跟随主题配色） |

  WAL 里能读到 `gently-mascot` / `Gently 小助` / `schema_version`——证明「前端 → pet_invoke →
  pet-core → 自己的 SQLite」这条链路是真的通了，不是只在单测里通。

### 3. 未做 / 下一步

- **M2**：宠物包导入（`pet.json` + 图集 → 预览 → 同意 → 安装），并把 `pet.state` / `pet.remove` 接到管理面板；

## 第八十九轮

> 起点：用户要求「先对整体计划做客观评估」。结论是方向可行，但有三处结构性缺口必须先补：
> ① 数据迁移只校验音乐库、旁挂文件写死了库名 → 有宠物数据后可能搬出坏副本；
> ② 契约守卫的域名白名单没有 `pet` → M1 一加命令就变成「没人守的第二份契约」；
> ③ 发现页文案把「估计的高潮位置」写成了事实。
> 用户拍板：**安卓计划延后，其余自行拍板**。

### 1. 本轮做了什么

| 事项 | 改动 | 为什么现在做 |
|---|---|---|
| **迁移 × 宠物库接缝** | `core/src/paths.rs`：旁挂文件改为**按后缀**跳过（`*-wal/-shm/-journal`，且**递归**生效）；迁移后对**每一份** `*.db` 做 `PRAGMA quick_check`；`commands.rs` 在迁移前先 `wal_checkpoint(TRUNCATE)`（新增 `Store::checkpoint_wal`） | 宠物库在 `<data>/pet/pet.db`，旧实现会把它的 `-wal` 热拷过去且不做校验——「迁移完好感度没了」是最难排查的一类事故 |
| **契约守卫扩到 pet** | 新增 `pet-core/src/contract.rs`（`PET_COMMAND_NAMES`，M1 前为空）+ `docs/contracts/pet-core-api.md`（信封 / 6 个错误码 / 命令表）+ `pet-core/tests/contract.rs`（Rust 清单 ↔ 文档表格双向）；`scripts/check-commands.mjs` 增加宠物域三查（命令表 ↔ 清单 ↔ 前端字面量、错误码） | AGENTS 第 13 条要求「契约只有一处」；不扩守卫，M1 一加命令就退化 |
| **文案诚实化** | `page.hot.discoverPreviewPlaying` 与设置页提示：「高潮片段」→「高潮段（位置为估计）」 | 契约里没有 chorus 时间戳，38% 处是估计；UI 不该把它说成事实 |
| **文档止损** | R84–R88 的详情节归档到 [`archive/rounds/R84-R88.md`](R84-R88.md)；本文件只留当前轮 + 最近三轮 + 入口 + 坑 + 下一步 | 本轮之前 STATE 已 425 行（自报预算 250 token），正在退化成日记 |

### 2. 验证

- `cargo test -p gently-core --offline --test data_dir`：**12 passed**（新增 2 项：宠物库随迁移一起走且 `-wal/-shm` 被跳过；
  宠物库坏了会**阻断**迁移并指出 `pet.db`）；
- `cargo test -p pet-core`：**12 passed**（10 项地基 + 2 项契约一致性）；
- `pnpm check:contract`：75 条音乐命令 + **宠物域 0 条命令 / 6 个错误码**双向一致；
- 守卫**负向验证**：临时往文档表格加一条 `pet.state` → 立刻报「文档里有、Rust 缺失 1 项」，恢复后转绿；

### 3. 未做 / 下一步

- **宠物 M1（建议下一轮）**：`pet.*` 命令同时进文档表格与 `PET_COMMAND_NAMES`、`src-tauri` 暴露命令、
  `src/pet` 渲染 `Frame`、用开关控制可见性；届时**必须**把 `check:reachability` 扩到 pet 命名空间
  （宠物契约 §4 已把它写成 M1 的验收项）；

## 第九十一轮

> 起点：M1 只把「出帧 → 画」跑通了，宠物还是程序化的那一个，**没有「宠物包」**。
> 目标（M2）：让用户能导入一个 `pet.json`（+ 可选图集），在界面里切换/移除，并且渲染器真的画出图集；
> 同时把 M1 留白的 `pet.state` / `pet.remove` 接上界面。

### 1. 本轮做了什么

| 层 | 改动 |
|---|---|
| 核心 | `pet.install{spec, atlas?}`：图集只收 **png/webp + 纯文件名 + ≤ 8 MiB**，落 `<data>/pet/packages/<id>/`，库里只记文件名（搬家后仍有效）；新增 **`pet.atlas{id}`**（base64 回传，带 20 行自带 base64 解码器，未引入依赖）；`Store` 增加 `atlas` 表 / `package_dir`；`remove` 连素材目录一起删 |
| 宿主 | 无需改动（`pet_invoke` 已经按契约名路由） |
| 前端 | `src/pet/core-pet.ts`：**一个渲染器画「当前出战的那只」**——读 `pet.state` → 取 `pet.atlas`（横向帧条，总帧数=各动画帧数之和）→ `background-position` 逐帧；没有图集退回程序化渲染。设置页新增宠物管理面板（列表 / 出战徽标 / 好感 / 换成这只 / 移除 / 导入：粘贴 `pet.json` + 选图集） |
| 状态 | `ui.petRevision`：安装/切换/卸载后 +1，让渲染器重新挂载（「什么时候需要重挂」只有一个来源） |
| 守卫 | `DELIBERATE_PET` 清空——7 条宠物命令全部有界面入口（管理面板 + 渲染器 + 点击） |

### 2. 验证

  `install{atlas}` → 文件落 `packages/<id>/` → `pet.atlas` 原样取回 → `remove` 连目录删；
  带路径/错误类型/空数据三类坏图集都被可读拒绝）；

  右下角小家伙同时在跑。

### 3. 未做 / 下一步

## 第九十二轮

> 起点：M2 让「宠物包」能装能切换，但宠物还**不会因为你的照顾而变**：好感只是个数字，
> 饿不饿也不影响任何表现。
> 目标（M3）：让数值产生**可见后果**——饿了有饿的样子、好感到档有亲近的表现、喂食能改变它们。

### 1. 本轮做了什么

| 层 | 改动 |
|---|---|
| 核心（行为） | 新增两个条件：`hungry`（阈值 `hunger_hungry_at`）、`bondAtLeast{tier}`（好感分档）；**阈值只在 `PetProfileLimits`**，宠物包只写「饿的时候演什么」；`Sim` 拿得到引擎的 `limits`（不再偷偷用默认值） |
| 核心（资料） | `PetProfile::mood()` 四档（shy/friendly/close/devoted）与 `is_hungry()`/`bond_at_least()`——**派生值，不落库**（库里只存好感与饿，避免两个真相） |
| 核心（命令） | `pet.state` / `pet.interact` 返回 `mood` + `hungry`；**`pet.state` 读前先结算一次时间流逝**（否则「关掉一夜」的宠物在面板上仍显示不饿） |
| 前端 | 宠物面板显示心情与「饿了」徽标、新增**喂食**按钮（冷却内核心报错、界面显示剩余等待）；内置小家伙升到 v0.2.0（新增「饿」动画与气泡），渲染器发现库内版本落后时**自动重装内置宠物**（用户导入的包不动） |
| 契约 | §2 补「行为表能写什么」：条件/动作清单 + 两条必须知道的语义（顺序即优先级；没有匹配就保持当前动画，想回待机要显式写） |
| 宿主 | `RunEvent::Exit` 里调一次 `pet.flush()`——退出不再丢最后 ≤200 帧的游走状态（在此之前只有 `Drop` 的隐式写回，进程退出顺序不保证） |
| 文档 | 新增 [`docs/pet-package.md`](../../pet-package.md)：`pet.json` 字段表、图集约定、行为表能写什么、会被拒的输入、安装/升级语义、现在做不到的事（给做素材的人看，不用读代码） |

- `pnpm smoke`：**483**；`pnpm check:contract`：宠物域 7 命令 / 6 错误码双向一致；`check:reachability`：留白 0；
- `pnpm verify`：7 道全绿；
- 打包版实图 `release/screenshots/r92-pet-mood.png`：面板显示 `Gently 小助 v0.2.0`（**升级成功**）、
  `出战 · 好感 2 · 拘谨`、按钮 `喂食 / 换成这只 / 移除`，右下角小家伙同时在跑；

### 3. 未做 / 下一步

- 饿/心情目前只影响**动画与气泡**，还没影响移动/交互强度（那需要位置行为，等 M4 一起做）；
- 喂食只有面板入口，宠物本体上还没有「投喂」手势（点击仍是触摸；加手势要先解决可交互区域与误触）；

## 第九十三轮

> 起点：M3 让数值有了后果，但宠物本体还是**程序化渲染的一个圆**；
> 用户给了一张 9 行的 sprite sheet（`examples/spritesheet.webp`），系统却只会画单行帧条。
> 目标（M3.5）：**让真素材直接可用**——网格图集、内置宠物换成真精灵图，顺手把素材校验收紧。

### 1. 本轮做了什么

| 层 | 改动 |
|---|---|
| 核心（规格） | `atlasLayout{frameWidth, frameHeight, columns, rows}` + `Animation.row`（不写按声明顺序）；校验：帧数 ≤ 列数、行号落在图里、有网格必须有图、有 `row` 必须有网格、格子尺寸/行列 > 0、行列 ≤ 64；**老的单行帧条一个字段都不用改** |
| 前端（布局） | 新增 `src/pet/frame-layout.ts`：规格 + 图片尺寸 → `[动画][帧] → {x, y}`（网格按格、帧条按总帧数等分），纯函数、不碰 DOM |
| 前端（渲染） | 渲染器按偏移表画；有图集时加 `.sprite` 类去掉程序化圆形底色（实测：不去掉就是一个紫球顶着精灵图）；内置宠物安装时**连同图集一起**交给核心（`fetch(打包后 URL) → base64`） |
| 资产 | `pets/gently-mascot/{pet.json, atlas.png}`：9 行网格、每格 192×208、9 个动画（idle/sway/fly/sleepy/curious/worried/sad/listen/annoyed）；内置宠物升到 **v0.3.0**（渲染器发现版本落后会连图集一起重装）；`atlas.png` 是用户给的 webp **去白底转透明**后的版本 |
| 守卫 | `pet-core/tests/atlas.rs` 7 项（含「仓库里那份包必须能过校验并装进图集」——包写坏了界面只表现为「宠物不见了」）；smoke +5；i18n 死键检查把 `pet.bubble.` 记为动态前缀（键写在宠物包里） |
