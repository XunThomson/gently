## 第八十八轮：宠物预开发 M0

> 起点：用户批准「先进行 pet（预开发，仍在 1.x）」，并纠正了早期草案的方向：
> **宠物存储归 `pet-core` 自己，不许与音乐核心耦合**。两个引擎（音乐 / 宠物）各自独立，
> 都只被宿主消费；UI（Tauri + React）是可替换的宿主，Rust 核心相对稳定。
> 音乐软件里**单宠物**展示，但多宠物要预留（宠物后期可能独立成仓库）。
> 喂食/好感度这类跨会话状态「要做，但不是现在」（先建地基）。

### 1. 架构纠正（用户拍板）

| 早期草案（作废） | 现在的决定 |
|---|---|
| `pet-core` 只做纯状态转移，**存储归 music core** | `pet-core` **独立 crate + 自己的 SQLite（`pet.db`）**；`gently-core` 不依赖它、它也不依赖 `gently-core` |
| 宠物渲染绑在 Tauri 窗口上 | 核心**不依赖 tauri**：只产出纯数据（`Frame`），宿主可替换（现在 React，将来可换 UI 甚至独立应用） |
| 宠物是「音乐软件的一部分」 | 宠物是**第二个引擎**，与音乐引擎并列；宿主负责转换（`Track → PlaybackHint`）与渲染 |

纠正的理由（用户原话要点）：强行关联等于把两个完全不同领域耦合，不利于后期开发；
UI 库仍在成长、可换，Rust 核心不会轻易改。该决定已写进 [`adr/0010-pet-core-crate.md`](../../adr/0010-pet-core-crate.md)（status: accepted）。

## 第八十七轮：三个实测 bug + 六项策略调整

> 起点：用户给了 `docs/BUG.txt`——要**先修三个 bug**，再做六项策略调整；

### 1. 三个 bug：根因与修法

| bug | 根因 | 修法 |
|---|---|---|
| 导入插件要重启才生效 | store 的 `plugin.loaded` 守卫让 `load()` 只在启动时读一次；导入面板自己又 `plugin.list` 了一份，装完只刷新了它自己；`core.sources` 的按源路由缓存还是旧的 | `PluginActions.reload()`（跳过守卫，强制重读 + `invalidateCoreSources()`）；导入/订阅安装/启停/卸载/改优先级全部走它；导入面板删掉私有清单，改订阅全局 store（唯一一份） |
| tab 与内容不一致（源收藏处稳定复现） | 换源/换分类是**异步**的且没有请求代号：A 的响应比 B 晚到就覆盖 B 的内容；`source-favorites` 还有「collections effect + load effect」两条互相触发 | 请求代号（`requestRef` / `epoch`）：换源/切分类**先清空再等**，回来的结果必须仍是最新一次，否则丢弃；换源改成一个 effect 走完「收藏夹列表 → 第一页」。榜单切片同修 |
| 休眠回来放不了 | ① 系统休眠掐断媒体元素，`audioUrl` 没变 → 没有任何代码去把声音叫回来；② 回环流代理 token 只有 30 分钟 TTL、上游直链更短，旧地址必然失效；③ `audioEngine.load()` 对同地址直接 return，error 态永远修不回来 | 引擎新增 `resume()/reload()/hadError()`：`load()` 在元素出错时不再跳过；`useAudioEngine` 在 focus / visibilitychange / pageshow / 5s 心跳上做「界面说在播但元素停着」的恢复；恢复失败且是错误态 → `recoverPlayback()`（重新解析、**保留进度**）；媒体报错时给同一批源**一次**自动重解析的机会（按 playId 限次，不做无限重试） |

## 第八十六轮：插件音质 / 换源 / 壁纸助手

> 起点：用户实测反馈两件事——网易云里部分歌曲播不了，而 MusicFree 等能播；
> 电脑负载时卡顿掉帧明显；另附搜索建议面板被页面内容盖住的截图。
> 先做可回滚的安全修复，完整插件 playback profile 与性能预算另立设计。

### 1. 定位到的根因

- **音质元数据是假的**：`catalog::merge_tracks` 把每个候选的 `qualities` 写死成
  `["standard"]`，`catalog_detail` / 收藏也类似；前端 `resolveWithFallback` 又直接把
  全局 `preferredQuality`（默认 high）交给每个源。只支持 standard 的插件会收到不支持的档位，
  返回 null 后整首歌被判“无法播放”。清单里的 `@qualities` 根本没被消费。
- **非聚合曲目只有单候选**：榜单 / 收藏 / 历史不是跨源搜索结果，播放时没有其它候选；
  当前实现没有“用户点一下去其它源找同一首”的入口。MusicFree 能换源，不是因为它的播放器绕过限制，
  而是它会重新搜索/换源。
- **网易云外链本身有限制**：随包的 `wangyiyun` 测试插件只走
  `song/media/outer/url`，会员/版权受限曲目会回 HTML 或 404；插件按设计拒绝，
  核心无法替它变出可播地址。需要登录、换插件或换源，不能承诺“所有网易云歌曲都能播”。
- **搜索建议层级**：标题栏有 `backdrop-filter`（会创建 stacking context），但没有显式 z-index；
  后绘制的路由内容盖住了 `z-index: dropdown` 的搜索面板。
- **性能**：`NowPlaying` 订阅整个 player，进度每 250ms 更新时整页（封面 / 标题 / 歌词）重渲染；
  歌词每次 timeupdate 重新 map 全部行。背景没有失焦暂停，窗口切走仍在解码 / 合成。

### 2. 本轮已做（安全批）

| 层 | 改动 |
|---|---|
| 核心候选 | `catalog::search` 把各源清单 `qualities` 带到 `candidates`；`catalog.track` 与收藏列表用 `PluginHost::qualities` 补齐，不再写死 standard |
| 前端播放 | `resolveWithFallback` 用 `pickQuality(candidate.qualities, preferredQuality)` 按源降级；`core.sources` 缓存核心清单的 qualities，补上桌面源（前端注册表为空） |
| 换源 | 播放失败时新增「换源」：按“歌名 + 歌手”调用一次现有 `catalog.search`，只合并当前候选之外的新源；用户点击才发起，不自动放大失败 |
| 搜索 UI | 标题栏 `position: relative; z-index: var(--z-dropdown)`，让搜索建议面板盖住路由内容；搜索联想改走 `catalogService.suggest`（优先用户指定/正在播放的源，否则核心第一个启用源），桌面端不再永远“没有结果” |
| 性能/内容 | `NowPlaying` 的进度下沉到 `NowPlayingLyrics` 子组件；`PlayerBar` 的进度条/时间下沉到 `PlayerSeekBar` / `PlayerTime`；歌词行与 `SourcePicker` / `QualityPicker` 用 `memo`；背景窗口失焦时**暂停视频但保持挂载**，静态网页也不消失；内容表面与抽屉/浮层分别有独立透明度和虚化控制（`--surface-content*`/`--surface-blur` 与 `--surface-drawer`/`--surface-drawer-blur`），文字/图标不受影响 |

### 3. 验证

- `pnpm typecheck` 通过；
- `pnpm smoke` **448**（新增：只支持 standard 的源在首选 high 时降到 standard；
  播放失败时显示「无法播放 / 重试 / 换源」；网页目录路径归一化/CSS 只内联本机资源；
  抽屉透明度/虚化独立于内容表面）；
- `cargo test -p gently-core --offline` 全绿（候选 qualities 断言已加到 merge 测试）；
- 打包版实测：搜索「万有引力」→ 网易云测试源失败 → 播放条出现「换源」；
  换源仍失败时说明当前源限制（插件只有 outer URL，且没有其它源返回同一首）；
- 内容透明度/虚化：浏览器 CDP 实测 `--surface-chrome` alpha 从 .66 调到 .20，卡片文字仍是

### 4. 壁纸准备助手（WE 路径）

- 设置页新增「壁纸准备助手」：不新增核心命令/文件系统权限；用户通过 `webkitdirectory`
  显式选择目录，文件只在本次渲染内读取。
- **静态网页打包**：`inlineWebWallpaper` 解析 HTML/CSS，把本机 CSS、图片、字体、
  `style` 属性里的 `url()` 转成 data URI；移除脚本、iframe/object/embed/form、`meta`/`base`、
  外部资源、`srcset` 和 `@import`，脚本与外链不会留下可执行/可联网路径。
  输出受 1 MB 上限约束（含 wrapper 余量）。
- 结果可「设为背景」（存 IndexedDB）或下载单文件 HTML；入口 HTML 可在多个 `.html` 中切换。
- 视频/Scene/Share JSON 不重复实现：视频仍走上方的「导入视频」；Scene 只说明“导出/录屏成视频”，
  不解析 `.pkg/.tex`；Share JSON 仍在上方背景卡解析，未知键显示未映射。
- 浏览器 CDP 实测：3 个文件（HTML/CSS/SVG）→ 内联 2 个资源、移除 1 段脚本与 1 个外部图片 →
  「设为背景」后当前背景为 `index-inline.html`，iframe `sandbox=""` 且 `srcdoc` 不含 `<script>`；
  打包版原生目录选择器仍需人工点一次（浏览器自动化不能可靠驱动 `webkitdirectory`）。

## 第八十五轮：本地视频背景 + 静态网页壁纸

> 起点：用户给出 Wallpaper Engine 类背景的集成方案。P1 做**本地视频 + 展示预设 + 静态单文件网页**；
> 不内建 `.pkg` 解密 / RePKG、不执行网页里的 JS、不新增核心命令——先把安全、可回滚的链路做通。

### 1. 范围

- 支持 mp4 / webm / m4v / ogg；用户在设置页通过 WebView 文件选择器导入；
- 视频 Blob 存 **IndexedDB**，localStorage 只存元数据 / 参数 / 预设；
- 网页壁纸只收**单文件静态 HTML/CSS**：HTML 也存 IndexedDB 的 `pages` store；
  iframe 用 `sandbox=""` + CSP 禁止脚本、网络、表单、外链；包装层去掉所有 `meta` / `base`，
  （含实体编码的 `meta refresh`），只允许内联样式和 `data:/blob:` 资源；
- 预设：保存当前参数、应用、重命名、删除；可粘贴外部壁纸工具的 Share JSON（只映射已知键，未知键保留并提示）；
  也可把当前参数导出成同一 schema 的 JSON（写入下方文本框，手动复制）；
- 恢复默认：移除当前视频/网页与参数，命名预设保留；背景回到内置/无；
- **整窗铺满**：标题栏 / 侧栏 / 播放条统一消费 `--surface-chrome`，视频开启时使用更透明的表面（light/dark 0.66），
  背景在整窗可见，而不是只在主内容区；
- **减少动态效果不强制**：默认跟随系统（`prefers-reduced-motion`），设置页提供「仍然播放」；
  用户显式覆盖后，系统动画偏好不再阻止背景；
- **不做**：`.pkg/.tex` 解析、RePKG/外部二进制、网页脚本、多文件/zip 网页壁纸、Wallpaper Engine 目录自动扫描。

### 2. 为什么这样切

- `.pkg` 是专有容器，内建解密有 EULA/版权风险；执行外部 RePKG 又违反“社区资源按不可信代码对待”。
- **带 JS 的网页壁纸暂不做**：iframe 沙箱能挡住 `fetch`/外链图片，却挡不住脚本把自身导航到外网；
  只靠 CSP/sandbox 无法可靠断网，完整 JS Web 壁纸需要独立 WebView + 导航拦截，是另一套安全设计。
  本轮先支持**静态 HTML/CSS**（CSS 动画、内联图片），链路、存储、UI 都可复用。
- 视频 Blob 放 IndexedDB：不扩大文件系统权限、不新增契约命令，浏览器预览与桌面端同一条路径；
  代价是清空站点数据会丢视频，设置页会检测并提示重新导入。
- 预设只保存**展示参数**，不承诺还原壁纸自身属性；未知键明确显示“未映射”。

  后续应把「视频 / 静态网页壁纸」当作**用户本机资源导入**（用户主动选文件），
  不预置任何壁纸地址，仍遵守 ADR-0005。

### 6. 复审修复（2026-10-24）

复审后按 P1 修了四件事，行为变更如下：

- **旧皮肤兼容**：`core/src/skin.rs` 增加有界 `RETIRED_COMPONENT_TOKENS`
  （`activeFontSize/activeBg/guideColor/guideWidth`）：旧皮肤仍能导入，退役键被丢弃并给 warning，
  不再整份 `skin.token_rejected`；新增核心单测。
- **resize 热路径**：`useShellMode` 只订阅形态字符串，App 不再每个 resize 像素重渲染外壳；
  浏览器预览的 `forceRegular` 改为形态变化时清除。
- **失败提示统一**：新增 `utils/playbackFailure.ts`，播放条与迷你播放器共用同一段原因
  （含失败源数量 / 媒体 detail）；迷你不再只显示泛化文案。
- **文档压缩**：历史轮次迁到 `docs/archive/rounds/R01-R83.md`；本文件只保留当前轮、最近三轮、
  历史入口与仍然有效的坑；`ROADMAP` 删除尾部重复轮次摘录；新增 `docs/GOTCHAS.md`。
